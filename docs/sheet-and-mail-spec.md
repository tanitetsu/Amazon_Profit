# シート＆メール取込仕様（決定事項）

正本。元メモ: `Book 3.xlsx`。実装時は本ドキュメントと `app/schema.py` 等を一致させる。

## ファイル・ブック構成

- ファイル名: `amazon-profit_{user_id}_{yyyy}.xlsx`（年が変わったら新規作成）
- 保存先: 運営 Drive `User_Acounting/`（変更なし）
- `user_id`: Gmail ローカル部（例: `asamiodaka`）
- **テンプレ**: `amazon-profit_TEMPLATE.xlsx`（ID は GCS 正本 `app_config.json` の `template_spreadsheet_id`。ローカルは `config/app_config.example.json` 参照）
  - **Agent／自動化はライブテンプレと bound Apps Script を変更しない**（依頼なしの再ビルド・API 再配備・表示切替なし）。運営の手動編集（表示状態・スクリプト Save 含む）はあり得る。新規は当時のテンプレ内容を copy 継承
  - シート: `ダッシュボード` ＋ `月次テンプレート`（ユーザー本は copy 直後に `hide_month_template_sheet` で非表示。テンプレ本体の表示は運営編集可／再ビルド時は表示推奨）
  - 新規ユーザー = Drive `files.copy` → 直後に `月次テンプレート` を非表示。見た目・結合・数式・保護・キャンセル☑連動 Apps Script はテンプレ継承
  - `月次テンプレート` の詳細は `DETAIL_DATA_ROWS=2000` 行分（行6〜`FORMULA_END_ROW`）まで横結合済み（空行含む）。☑はテンプレに付けない
- ダッシュボードは 13 列（販売総額〜返品）。`rowCount` 固定（月別スロット最大12）
- 既存本番シートは移行しない。**同一新レイアウトの新規ファイル**から開始する

## 月次シートへの振り分け

- **注文日**の年月で対象月次タブ（`YYYY-MM`）を決める
- 該当月次が無ければ **`月次テンプレート` を duplicate** して作成・表示（シート名＝`YYYY-MM`。ユーザー本では種シートが非表示のため duplicate 後に表示化）
- 追加月が「最新月の翌月」でない場合、**間の月のシートも作成**し、ダッシュボード月別内訳も同様に埋める
- 月別内訳はいったん書いてから **降順に並べ替え**。タブ順も降順（新しい月が左）
- 明細行は終端行の一つ下へ **APPEND**（値書き込み＋当該行の仕入/発送/キャンセル/完了に☑ validation）
- 自動更新のたびダッシュボード2行目の **最終自動更新** を書き換える
- 年をまたぐ注文は、注文日の年のファイルへ書く（ファイルが無ければテンプレから作成）

### 行構成（月次）

1. 年月タイトル  
2. サマリーラベル  
3. サマリー値  
4. 注意書き `青い列のみ編集可能です`  
5. 詳細ヘッダー  
6〜. データ

### 利益（行）

- 状態が `○`: 売上金・仕入金の両方あり → `売上金 - 仕入金 - 諸費用`。否則空欄
- 状態が `○` 以外: `-1 × 諸費用`（ゼロなら空欄）。負は赤文字
- 実装は `INDIRECT("列"&ROW())`（仕入金・諸費用などの参照）。青い列は**値の上書きのみ**。切り取りや「セルを削除」すると隣接の利益式が `#REF!` になり得る（利益列は保護のため一般ユーザーは直せない）

### 状態

| 値 | タイミング | 行書式 | 追加 |
|---|---|---|---|
| ○ | 注文取込時 | なし | |
| × | 購入者キャンセル検知時 | グレー | キャンセル☑を編集不可に |
| - | キャンセル☑が ON（Apps Script onEdit・即時） | グレー | |
| 返品 | 返品承認 / A-to-Z 検知時 | 薄い赤 | キャンセル☑を編集不可に |

状態ラベルコメント:

- ○：取引成立中
- ×：購入者からのキャンセル
- -：あなたによるキャンセル
- 返品：返品要求

### キャンセル☑ → 状態（Apps Script・即時）

- テンプレに保存済みの simple `onEdit` が正。**Agent は API 再配備しない**（プロビジョン／Excel 取込でも同様）。運営がテンプレ上で手動 Save／差し替えした場合、以降の新規 copy はその内容を継承する
- 挙動: ☑ ON → ASCII `-`（`×`/`返品`は維持）。OFF かつ `-` → `○`。状態が `返品` のときフォント小、それ以外は大

### 完了☑の条件付き書式

- 行全体を薄いグレー
- 状態の × / - のグレーより完了は弱い側。**×・-の書式を優先**
- 状態が ○ または 返品のときの色に対しては **完了のグレーを優先**

注意書き（サマリーの下・ヘッダーの上）: `青い列のみ編集可能です`

## 月次シート — サマリー欄

売上系（税込販売額・手数料・Pt・売上金）: 詳細の同項目合計。**状態が ○ のもののみ**

- 仕入金・諸費用: 詳細の同項目合計（**状態フィルタなし**＝キャンセル/返品行の仕入も合算してよい）
- 利益: 詳細列「利益」の合計（`SUM`）。行利益式の総和であり、サマリー売上金−仕入金−諸費用ではない
- 利益率: `(利益 − 諸費用) / 売上金`（売上金が 0 なら空欄）
- 注文: 詳細レコード数（状態フィルタなし）
- 発送: 発送☑ ON の個数
- キャンセル: 状態が `×` と `-` の合計（サマリーラベル「キャンセル」改行なし・10pt）
- 返品: 状態が `返品` の個数

### 列幅・見た目（正本: 2026-04 ライブ）

- **最小単位**: 詳細 10pt 相当で 1 単位列 = `UNIT_PX=7`
- **詳細**: 仕様の単位数だけ横結合（例: 注文番号20・SKU17・商品名30・日付系8・状態6・金額系は列ごと定義）
- **サマリー**: 左端は **SKU 開始列**。単位幅は明示（税込販売額13 … 注文/発送/キャンセル/返品は各10）。値行（3行目）は塗りなし・黒字・14pt。ラベル12pt（キャンセルのみ10pt・改行なし）
- **サマリー色**: 税込販売額・手数料・Pt＝黒地白字／売上金＝青地白字／仕入金・諸費用＝オレンジ地白字／利益・利益率＝緑地白字／件数系＝薄灰地黒字。外枠太・内罫細
- **状態値**: 上下左右中央・20pt（値が `返品` のときのみ10pt）
- **日付表示**: `m/d`
- **最終行**: `FORMULA_END_ROW`（`DATA_START_ROW + DETAIL_DATA_ROWS - 1` = 2005、`rowCount`）。詳細スロット `DETAIL_DATA_ROWS=2000`。列幅は全列 `UNIT_PX` 単位で最終行まで同一。データ行高は詳細全行 32px。テンプレ時点で詳細は横結合済み。チェックボックス（仕入/発送/キャンセル/完了）は注文 APPEND 時に当該行へ付与
- Overview は 13 列（販売総額〜返品）。正本は現行ライブ Overview
## ダッシュボード

正本: Drive テンプレの `ダッシュボード` シート

- 見出し「サマリー」「月別内訳」
- 行: 1タイトル / 2メタ（新規時に生成） / 4サマリー / 5ラベル / 6値 / 8月別内訳 / 9ヘッダー / 10〜21 月別スロット（最大12）
- `rowCount` 固定（`OVERVIEW_ROW_COUNT`）。年間 KPI の SUM は **B10:B21 相当を広めに固定**（空行は無視）
- テンプレでは10行目以降は値・罫線なし。月追加時に行を書いて降順整列＋罫線付与
- メタ例: `ユーザー … · ファイル … · 期間 … · 最終自動更新 YYYY-MM-DD HH:MM`
- 列順: 販売総額 / 手数料 / Pt / 売上金 / 仕入金 / 諸費用 / 利益 / 利益率 / 注文 / 発送 / キャンセル / 返品
- 月別・タブとも **降順**（新しい月が上／左）

## メルカリ仕入・リンク

- SKU が `m_m` + 数字（例: `m_m42688576128`）のときのみ対象
- メルカリ商品 ID: 先頭の `m_` を除き `m42688576128` 形式 → 商品名セルに `https://jp.mercari.com/item/{id}` を HYPERLINK
- それ以外の SKU（`ms_…` / `z_…` / `r_…` 等）は仕入取得もメルカリリンクも行わない
- **価格取得**: `GET https://api.mercari.jp/items/get?id=…`（DPoP・アカウント不要）。売却済みでも `price` があれば仕入金へ。失敗・404 は空（取込は継続）
- 実装: `app/mercari.py`（価格）／`app/sheet_links.py`（リンク。Excel 取込・メール APPEND 共通）
- リンクは **「リンクを挿入」形式**（`textFormatRuns.link`）。ホバーでプレビュー／サムネが出るのはこの形式。`=HYPERLINK()` 数式はクリックはできるがプレビューが出にくい
- ブック locale は `ja_JP`。もし数式を使う場合のみ引数は **`;` 区切り**

## 注文詳細リンク

- 注文番号（`999-9999999-9999999`）から Seller Central 注文ページ URL を組み立て可能
- 形式（注文確定メールの redirect 先と一致）: `https://sellercentral-japan.amazon.com/orders-v3/order/{注文番号}`
- 注文番号セルに HYPERLINK。メール内の `/buy-shipping` 等のクエリは不要
- **自動書き込み（APPEND）時も** `order_id_cell` / `title_cell` 経由で同じ HYPERLINK を付ける（`app/sheet_links.py`）

## 取込の再試行（ポーリング）

- `apply` が例外 → その Gmail message id は `seen` に入れない → 次回ポーリングで再処理
- **注文**: 明細は 1 行ごとに値書き込み直後に ☑ validation ＋ リッチリンクまで完了させる。途中失敗しても完了済み行は☑/リンク付き。再処理時は既存 order+SKU を **ensure**（空の自動列のみ埋める＋☑/リンク再付与）。手動列・非空の自動列は上書きしない
- **キャンセル／返品／A-to-Z**: 一致行が 0 件のときは `defer_seen`（`seen` しない）。注文行が後から付いたポーリングで状態を書く。注文番号自体が取れないメールだけ `seen` 確定
- パース欠落対策: 注文日／出荷予定／注文番号ラベルは半角・全角 `:`/`：` 両対応。ensure で空セルを同一メール再処理時に補完

## 検知対象メール

| 種別 | 抽出 | アクション |
|---|---|---|
| 注文確定（1点） | 注文番号・注文日・出荷予定・商品名・SKU・税込価格・手数料・Pt(任意)・売上金・注文詳細URL | 注文日の月次へ新規行。状態○。注文番号に注文詳細リンク。可能なら商品名にメルカリリンク。Pt無ければ税込×1% |
| 注文確定（複数） | 同上（明細ごと） | **SKU 単位で1行ずつ** APPEND。プレースホルダ SKU（`N点の商品が販売されました`）は空に正規化（`order_sku.normalize_sku`） |
| キャンセルリクエスト | 注文番号（SKUあれば併用） | 一致行の状態を `×`。SKU無しなら注文番号一致の**全行** |
| 返品承認 | 注文番号（SKUあれば併用） | 状態を `返品`。SKU無しなら注文番号一致の**全行** |
| A-to-Z保証 | 注文番号（SKUあれば併用） | 即 `返品`（運用で見直し可）。SKU無しなら注文番号一致の**全行** |

### 対象外

- 返金手続き開始メール（不要）

### 行特定ルール

1. 注文番号 + SKU が取れる → 両方一致する行
2. 注文番号のみ → その注文番号の**すべての行**に同じアクション

## 未決・実装時にコードで固定してよいこと

- Pt の 1% 計算の丸め: **半分切り上げ**（`int(price * 0.01 + 0.5)`）
- メルカリ価格: `items/get` + DPoP（キャッシュなし。Excel 取込時は元シートの仕入を優先し、空かつ対象 SKU のみ API 補完）
- Seller Central 注文詳細リンクの有効期限切れ時の扱い（取れない場合はリンクなし）
- キャンセル☑ → 状態 `-` はテンプレ継承の Apps Script `onEdit`（上記）
